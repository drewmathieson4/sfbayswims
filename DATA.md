# Data dependencies — what the apps rely on, how it fails, and what we do about it

Audit of 2026-08-25, both products (the Planner at `/`, the Frame at `/frame/`). Everything below is implemented
unless marked *chore* (a human task) or *later*.

## 1. The sources

| Data | Source | Refresh | Cache | If it fails | On screen |
|---|---|---|---|---|---|
| Tide extremes | NOAA CO-OPS 9414305 North Point, hi/lo | live window ±36 h every 30 min (only if the cache is older than 6 h or doesn't cover now −12 h … +30 h) | `localStorage ap.tides` + the year bundle `data/tides-<year>.json` (this year and next, merged) | the bundle's predictions carry on; live only patches the near term | nothing changes (the tide rate only feeds the cove's fill/drain and the height line) |
| Cove current | NOAA CO-OPS SFB1204 (Alcatraz SW), bin 18 | live window ±36 h every 30 min | `ap.currents` + `data/currents-<year>.json` | the bundle's prediction (`≈` on the HUD when a value is clamped or derived) | `flood ≈1.2 kn` |
| Bay currents | NOAA CO-OPS predictions for 43 stations | none live — bundle only (`data/worlds/bay/currents-<year>.json`) | — | past the bundle's end each station clamps to its last value, flagged `≈` | `≈` on the reading; the horizon note (§2) |
| Water temperature | USGS 374938122251801 Alcatraz → USGS IV → USGS Pier 17 → NOAA 9414290 → CeNCOOS Tiburon → **day-of-year climatology** | every 10 min (and when the tab becomes visible) | none (climatology is bundled) | the next source; last the climatology, which always exists | `water ≈63°F` from climatology; a live reading older than 3 h shows `≈` and `· 5 h ago` |
| Wind | NWS FTPC1 Fort Point → Open-Meteo | every 15 min | none | hidden — it is informational only, never in the physics | nothing; older than 2 h shows `· 3 h ago` |
| Sun | computed (NOAA solar algorithm) | — | — | can't fail | — |

Live fetches are made **by the visitor's browser**, so rate limits are per person and the site has no server to go
down. No key, no account, no tracking.

## 2. The bundled year — the one real chore

The physics needs predictions well beyond what live windows give (a Bay swim starts hours from now; best-starts
searches days). Those come from bundles committed to the repo, generated by `tools/precompute_tides.py` and
`tools/precompute_currents.py`. **Today they reach 2027-01-10 (currents) and 2027-01-20 (tides)** —
`python3 tools/check_bundles.py` prints the current state and exits 1 when anything ends within 60 days.

What happens past the end without action: the cove's tide rate goes to 0 (no fill/drain), every current station
clamps to its last value with `≈`, the timeline's curve flattens — the app keeps running, but the numbers stop
meaning anything. So:

- **In the app:** the result card says *beyond the bundled predictions (they reach Jan 10)* when a swim ends past
  the horizon; best starts search only up to it and say so; the *About the numbers* sheet states the horizon; the
  Frame shows *predictions end Jan 10 · update the frame* for the last three weeks (`horizonWarnDays`).
- ***Chore, every December:*** run the three commands in `tools/check_bundles.py`'s docstring for the coming year,
  commit, push. The site picks the new files up (the engine loads this year's and next year's bundles together, so
  there is no restart at New Year). The Pi frame does it by itself — `tools/pi/refresh-bundles.sh` on a December
  cron — and needs only network.
- ***Later:*** a GitHub Action that runs `check_bundles.py` monthly and opens an issue when a bundle is ending.

## 3. Failure modes, one by one

- **NOAA / USGS / NWS down or changed** — each fetch is isolated (its own try/catch, 12-s timeout), records
  `state.data.health[source]` = ok / failed with the error text, and the app falls back as in §1. A fetch that starts
  returning a different shape throws on parse and lands in the same place. Nothing else stops.
- **The Bay's currents** have no live feed by design (43 stations × 6-min data would be 43 requests every refresh);
  they are predictions either way, so the bundle is the source of truth.
- **No network at all** (a beach, a frame in a house with the router off) — the bundles and the climatology carry
  everything the physics and the picture need. The Frame shows *no wi-fi · join "aquatic-park" to set up* after
  3 minutes of failures (kiosk only). The Planner shows `≈` where it applies.
- **Year rollover** — both this year's and next year's bundles load when present; nothing to restart.
- **Clocks and time zones** — every time is computed in America/Los_Angeles from the visitor's clock; DST is handled
  in `localToEpoch`. A wrong device clock skews "now" but not the predictions.
- **Corrupt `localStorage`** (settings, favourites, caches) — every read is guarded; a bad value falls back to the
  defaults, *reset settings* clears them.
- **A JavaScript error** — one listener throwing is reported and skipped, never blocking the others (`state.js`);
  errors in the physics or the animation loop are caught and reported; the Planner shows a banner (*Something went
  wrong … reload · report*) with the error; `window.onerror` and unhandled rejections are captured for the report.
- **GitHub Pages down** — rare and short; the Frame runs from its own Pi and never depends on it.
- **A mis-drawn route** (a leg over land) — the draw mode warns; the physics still runs.

## 4. Redundancy in the code (what makes bugs "not too bad")

Isolated fetches with health records · bundle + climatology fallbacks with `≈` on screen · staleness ages on live
readings · the prediction horizon surfaced in three places · listener isolation · caught loop/recompute errors with an
error banner · guarded storage · `?offline=1` and `?frames=` for testing without the network or a visible tab ·
`tools/check_bundles.py` for the chore.

## 5. Reporting a bug

*Settings & controls → Report a bug* (also from the banner and the About sheet). The report contains the app version,
what the user typed, the plan as a link, the spot/swim/start/pace/units, the physics result, every data source with
its age and health, the bundle horizon, the browser and viewport, and the last errors — nothing personal. *Copy
report* puts it on the clipboard; *open an issue on GitHub* prefills a new issue in this repo; an email option appears
when `CONFIG.feedback.email` is set.

## 6. Checklist

- Monthly: `python3 tools/check_bundles.py` (or watch for the in-app horizon notes).
- December: regenerate next year's bundles; commit; push. Confirm the Frame's cron did the same (`ls /opt/aquatic-park/data`).
- After a NOAA outage: nothing — the next refresh heals; a stale tag disappears by itself.
- After a report: the *Errors:* line and the *Plan:* link reproduce most things.
